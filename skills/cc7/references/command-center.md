Use this when an owner explicitly asks to build a complete Command Center or one
of its views. It complements CC7 Health and DASHBOARD7; it does not replace their
existing audit/setup rules. No recurring process is enabled by copying a prompt.

## First useful result

A private local page with the selected views, built around the owner's existing
files. For an empty brain, a clearly labelled blueprint is the first result;
use the public onboarding starter before claiming a working system. Ask at most
three material questions: desired outcome, allowed sources, and visibility.

The Nora Vale / Vale Studio example is fictional. Reuse its layout and controls,
never its clients, tasks, amounts, audit dates or healthy states as owner data.
The example ZIP opens through its standard-library local server; see its START.
It includes both languages, fonts, source HTML and real GitHub method links.

## Adapt, do not clone the facts

1. Read the chosen brain's short entry points and existing project/task map.
   Preserve the owner's constitution, folder names, IDs and current writers.
   Inspect only permitted files. No broad crawl or secrets scan is implied.
2. Pick one recurring decision the page should help. Start with the requested
   view or a small dashboard. A missing source stays unknown, never a zero.
3. Map each card to an existing source and check date. Projects need a next
   action and owner; a Gantt needs actual or explicitly proposed dates. Read
   existing tasks instead of creating another task or CRM database.
4. Apply the owner's privacy rules before rendering. Financial and relationship
   material stays private; show only aggregates the owner approves. The public
   example's privacy choices do not amend the owner's constitution.
5. Reuse the example's compact design, keyboard controls and saved light/dark
   choice. When bilingual, pair EN/LV routes and translate charts, labels,
   prompts and accessible names. Hosted views/tabs have clean path URLs;
   fragments are for genuine anchors in the same content.
6. Save the result in the existing project/output home and read it back.
   Check direct URLs, reload, Back/Forward, mobile, both languages/themes and
   the source behind one real card. Test access before publishing private data.

Copying the instructions is not installation. An AI without file access can
prepare a plan; one without web access can use the included essential steps and
ask for the downloaded package. Say what was actually saved and tested. Do not
claim account connections, live updates or autonomous work from a page alone.
Publishing, new connections, spending, sending and schedules need the owner's
specific authorisation. Build locally first unless publication is requested.

## Done

The owner can find one useful next step, open its real source, and understand
which work still needs a person. List files written, checks performed and any
remaining setup. An unrun method and an unaudited layer stay visibly unverified.
