# TOOLS7 · the tool and access inventory

Parent: [CC7 Command Center](command-center.md). Portable workspace recipe,
2026-11-13. This builds a truthful inventory, not new account connections.

Read the owner's existing Tools layer and permitted connector list. For each
relevant service record: purpose, account alias (no credentials), operator or
connection path, allowed read/draft/write actions, actual last check, evidence,
cost boundary if relevant, and the unresolved next step. Keep one canonical
record per service; link the dashboard to it instead of maintaining a copy.

Distinguish listed, configured, actually tested, unavailable and unknown. A tool
name in instructions is not a working connection. A successful read does not
prove sending, publishing or deleting; old evidence does not prove today's
access. If the owner asks for a live check, agree its exact scope and use the
existing permitted operator. Never make a payment, send a message, create an
account or enable a schedule to decorate an inventory.

Show a short actionable summary and put detailed dated logs one level deeper.
Keep tokens, balances, raw client data and private identifiers out of a public
page. Do not claim a failed, blocked or unperformed test passed.

Completion: each displayed state has a source/date or a visible unknown reason;
the view links to the actual inventory; no new integration is implied.

Related: [CONTEXT7](../../context7/SKILL.md), [AUDIT7](../../audit7/SKILL.md),
[SKILLS7](../../skills7/SKILL.md). This is a workspace recipe, not the owner's
private service registry or a portable credential bundle.
