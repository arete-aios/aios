# Optional source monitoring

Parent: [SKILL.md](../SKILL.md). Source activity and communication decisions are
separate stages, even when one authorised workflow coordinates both.

## The activity stage

An accepted source reader may synchronise new or changed messages on an agreed
schedule. The owner selects the account, readable scope, cadence, private
notification route, storage and failure handling. Package installation, an import
receipt or a human HTML guide is not proof that a runner or schedule is active.

Reconcile stable account-qualified source IDs and the previous accepted baseline.
An initial history import is a baseline, not a burst of new-message alerts. Stay
quiet when the source is unchanged or an event was already handled. Notify only
within the accepted purpose: for example a new incoming item or a material
coverage failure. Do not manufacture a recurring “nothing changed” update.

## The semantic review

An activity event says that evidence changed; it does not establish whether the
owner owes a reply or delivery. COMMS7 checks the full selected exchange, latest
sent and draft context, prior owner decisions, real deadlines and relevant goals.
Only this review supports an Action, Waiting, deferred item or no-action decision.

Examples: a new “thanks” creates no task by itself; an already-sent reply can remove
a proposed reply; an old promised file stays open without a fresh message; a
notification with inaccessible content is a coverage gap, not a known request.

## Acceptance and permissions

Test the selected source and identity, baseline import, one real relevant change,
one unchanged cycle, duplicate suppression and a visible failure path. Distinguish
the reader's evidence, runner activity and actual delivered notification. A label
writer, outbound sender, filter/unsubscribe writer and scheduler are separate
capabilities whose concrete actions need the task's existing authorisation.

If no accepted runner is available, use an on-request manual review. Do not install
a scheduler, broaden account scopes or route personal messages into shared memory
just to make the diagram look complete. No owner-specific schedule, account or
notification destination is supplied by this community package.
