# Gmail GTD labels, filters and subscriptions

Parent: [SKILL.md](../SKILL.md).

| State | Label meaning |
|---|---|
| Action | A concrete next action owned by me. |
| Waiting | A specific result owed by another person, with check date/trigger. |
| Someday/Maybe | An optional idea that has not become a commitment. |
| Read/Later | Material deliberately retained for reading. |

Inspect existing names and IDs per account; avoid creating duplicate label systems.
Classify the conversation's meaning, not the unread flag. Current messages can
justify both Action and Waiting when the thread has distinct open obligations.
Keep the task's actual status in its existing authority.

For a bounded authorised label change:
1. Confirm account identity, selected message IDs, current labels and intended diff.
2. Apply only the accepted classification; preserve unrelated/system/read labels.
3. Read back the same messages and report applied, failed or unverified separately.
4. Retain prior label IDs for a scoped rollback; stop on identity or readback mismatch.

For filters, show stable sender/list/subject criteria and exact intended effects.
Do not route Action or Waiting out of view. Dynamic task interpretation is not a
safe static filter rule. For unsubscribe, identify low-value repeated subscriptions,
check that essential invoices/security/service messages remain, and execute only
the accepted change with a supported route. An available reader does not establish
filter/unsubscribe writing capability. Otherwise provide a concrete unsaved proposal.
