# COMMS7 in the AIOS system

Parent: [SKILL.md](../SKILL.md).

**Purpose of this section:** show how dependent this skill is on the wider system,
what each layer contributes to the actual decision, and what a standalone review
loses. A generic list of five layer names is not sufficient.

**System integration: high — qualitative, not a measured performance score.**
A standalone review works with supplied exchanges, goals and previous decisions.
An integrated review can recover those facts from their maintained sources, so
prioritisation reflects the owner's real direction and current work.

| Layer | Input to COMMS7 | Why it improves the decision | Accepted output |
|---|---|---|---|
| Constitution | North Star, working principles, privacy and action rules | A loud message does not outrank a strategic commitment merely because it is unread. Explicit deadlines and real obligations still matter. | A reasoned recommendation within the owner's boundaries; no silent rule change. |
| Memory | Relevant project history, relationship context and previous outcomes | Avoids asking a resolved question, resurrecting rejected work or missing a promise made elsewhere. Correct filing makes that learning available next time. | Minimal accepted business conclusion in the existing project/CRM record; private source material retains its protected audience. |
| Skills | FOCUS7 priorities, CRM7 relationship method, related delivery methods and permitted agent roles | The communication review hands work to the method or responsible person that can finish it. It does not duplicate a CRM, project or agent. | A concrete handoff and link to the authoritative record. |
| Tools | Shared catalogue of permitted mail, messaging, CRM, calendar and file tools | Uses the same verified connection as other work; no separate credentials or imagined scopes per skill or agent. | Exact authorised operation and readback, or a named missing capability. |
| Focus | Accepted active goals, projects, tasks, capacity and deliberate pauses | Distinguishes what matters now from an attractive distraction. A paused project is not reactivated by a fresh message. | Proposed next action or priority update, accepted through the existing task authority. |

## One practical example

Two messages arrive: a generic promotion and a request for material promised for
an active customer workshop. Both are unread. Focus identifies the workshop;
Memory confirms the promise; Constitution explains why this kind of delivery fits
the owner's direction. COMMS7 recommends checking and sending the promised material,
while the promotion usually needs no reply. If a promotion has a genuine consequence
or the workshop was completed by a phone call, newer evidence changes the result.

This is the value of integration: context changes the selection. It is not evidence
that every connector is installed or that the AI always makes the correct decision.

## One authority per data type

Tasks remain in the owner's task system; CRM-owned fields remain in CRM; project
facts stay in their project. COMMS7 keeps a derived review/handoff that references
those records. A saved checkpoint is not a second task database. Draft a concise
CRM note or Focus change when useful, preserve IDs and use the accepted writer.
If one dependency is unavailable, disclose the limitation and use the permitted
manual path; do not invent or silently broaden access.
