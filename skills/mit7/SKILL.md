# MIT7 — Choose achievable outcomes and close the day

MIT7 turns current project facts and available time into up to three meaningful daily outcomes. You choose; AI prepares only authorised work. At closeout, preserve what happened, evidence and the next action. This is a consolidated method, not a recovered historical app or an installed automatic morning/evening service.

## Start and install

Read [INSTALL.md](INSTALL.md) for a small first run. In a general AI chat, attach this instruction and [the method](references/METHOD.md), then provide your accepted direction, current project facts and work window. In a skill-capable host, install this complete folder using that host’s documented skill location. Folder presence does not establish activation or account access.

> MIT7 — using my accepted direction, latest project facts and today’s time window, propose up to 3 feasible outcomes with done criteria, next actions and my required minutes. I choose.

Use for “what should I finish today?”, replanning or closing accepted daily outcomes. A request to explain MIT7 or generate its guide changes only method/view content. Weekly priority reconciliation, communication review and actual domain delivery belong to their appropriate methods.

## Decision rules

Read [METHOD.md](references/METHOD.md) before planning or closeout. Start with the user’s accepted direction and priorities. Check the latest project decision and delivered artifact before trusting an old open task card. Completed work must not restart because a card is stale. Distinguish a promised deadline from a suggested work date.

Check an authorised calendar or the user’s stated work window. Mark assumptions when the calendar is unavailable; do not claim time is free. Separate the user’s required minutes from AI preparation. Minutes are estimates, not measured capacity or a delivery guarantee.

Propose up to three feasible outcomes. Each needs: why today, a testable done criterion, project source, responsible person, next action, minutes and dependencies. Several cards can contribute to one outcome. Show that mapping and respect the chosen tracker’s actual limits; MIT7 imposes no particular database or card model.

The user chooses. A recommendation, an assignee name or a tool’s suggestion badge is not an accepted choice or a dispatched job. Save only the specifically authorised selection and verify it by reading back the same records. Do not ask again for a clear permission already given. Preparation/delegation and external changes remain within the task’s actual authorisation.

Preserve delivery evidence in the existing project home and update the same authorised tracker. At closeout, record **completed, waiting, blocked or continuing** for every chosen outcome, with evidence, reason and next action. State the actual selection date; an old selection is not “yesterday”. Do not automatically select unfinished work for tomorrow.

## Sources, tools and output

Define which source owns which fact: the tracker stores accepted selection/status/history; the project stores context, decisions and delivery evidence; current priorities express accepted attention. A morning brief is one source, not proof of full coverage. Do not create a competing task database.

Minimum output is a reviewable proposal. After a clear choice, it may be an authorised saved selection with readback. Closeout is a dated outcome record with evidence and a next step. Distinguish proposal, acceptance, execution and verification.

This package has no Python helper, database, account client or scheduler. It works with supplied text and one existing list. Calendar/tracker connections are optional external dependencies that must be checked and authorised in your environment. The [APP guide](https://app.areteaios.com/learning/skills/mit7) is a local explanation; it performs no account action. [READINESS.md](references/READINESS.md) states practical limits.

This context improves personal relevance. Standalone use needs only those inputs in plain text and one chosen tracker.
