## The rule for this folder, and it is the only one

**File mode:** eleven method folders are in here. Three are switched on and eight are present files
that wait. **Owner-saved mode:** no method folder is claimed to exist; this file registers eleven
methods available from their exact public source, with the same three switched on.

**Switched on, which this method calls standing:** the trigger line is in my constitution. My AI reads
it on every message, and the method can run without me asking for it.

**Present, in file mode:** the skill file sits in this folder and is listed below. **Available, in
owner-saved mode:** the row and exact fetch rule exist, but the folder does not. Both cost no loaded
context and wait for the owner to type the trigger.

**A fourth one does not get switched on until one of the three has run without me asking, once, and
what came back changed what I did next.** That is the whole cap and it is the only rule in this
system that costs me something. The reason it is here: almost nobody returns to one of these after
three weeks, and the reason is always the same, they installed twenty methods before the loop ever
closed once, so nothing they wrote down ever came back to them.

Assistant: when I ask for a fourth standing skill and the loop has not closed once, say no and name
the open test. The refusal is the method working, not you being difficult. Say it once, write it in
the progress record with the date, and do not argue twice.

## The eight that wait

Nothing below runs unless I type its name. Five of them are the methods behind steps my onboarding
already ran by hand, so I can redo any of those steps properly without going back to the repository.

| Skill | I will want this when | Trigger |
|---|---|---|
| `constitution7` | My AI gets something wrong it should have known. The mistake names the missing line | `CONSTITUTION7` |
| `memory7` | My folders stop fitting, usually once real material has arrived | `MEMORY7` |
| `braindump7` | The dump file has grown past reading | `BRAINDUMP7` |
| `deepdive7` | I want the full inventory of what I have to work with, not the first pass | `DEEPDIVE7` |
| `north7` | The quarter turns, the north star changes, or a weekly review produced decisions and there was nowhere to write them | `NORTH7` |
| `week7` | Every week, on my day. This is the one that marks last week's promise kept or not kept | `WEEK7` |
| `eval7` | I want to know how good one thing I already have actually is | `EVAL7` plus the thing |
| `evalx` | I have a real choice with a real cost and two to six options | `EVALX` |

**`week7` is not standing, and that is deliberate.** What reminds me is the Accountability block in
my constitution, which speaks on my review day when the review has not run, and the calendar event
set up during the onboarding. A reminder is a rule. It does not have to be a fourth standing skill.

**Owner-saved mode fetch rule:** the exact source for every row is
`https://raw.githubusercontent.com/arete-aios/aios/main/skills/<name>/SKILL.md`, replacing `<name>`
with that row's skill name. Open it when the trigger fires; never describe it from memory and never
claim a local folder exists.

**The first one to add after these:** `context7`, the day this system grows past the point where I can
scan it. The full library is in `00-system/aios/skills/`.

## Registration lines, for when one of these gets switched on

Copy the line into the constitution, under the three that run, and only after the cap allows it. The
paths below use this folder's real name. The skill files in the public repository write them as
`skills/<name>/SKILL.md`, because they are written for any system, not this one.

```
WEEK7, once a week on the same day. Read the week's own records, not my memory of it. Check the
ledger first, filled from evidence rather than memory. Money in, out, left. Patterns across weeks,
not events inside one. Max three decisions, each a ledger row with a check date and an evidence
source, then update focus. You draft, I correct. Spec: 03-skills/week7/SKILL.md
```

```
CONSTITUTION7. This file is the core. It stays short enough to load every message, every line changes
what my AI does, and it points at the other layers rather than containing them. Revise when reality
moves, not on a schedule. Spec: 03-skills/constitution7/SKILL.md
```

```
MEMORY7. My memory layer: a small set of areas named in my words, one folder holding only my own
material, machinery outside it, plain files only. One fact, one home. A new area appears when an
existing one is too big to scan, never in advance. Spec: 03-skills/memory7/SKILL.md
```

```
BRAINDUMP7. My brain dump zone. Show, dispatch by topic, or archive, always on my OK, and a line
there is never a task until I say it is. Spec: 03-skills/braindump7/SKILL.md
```

```
DEEPDIVE7. My inventory lives in memory: who I am, what I have, what is in the way, each item scored
0 to 10 for the next twelve months. My money disclosure level is [everything in / summary only /
nothing]. Never plan against a resource that is not in it. Spec: 03-skills/deepdive7/SKILL.md
```

**`north7`, `eval7` and `evalx` do not get a constitution line at all.** `north7` is a build skill
that runs once and then gets out of the way. `eval7` says of itself that it is never self invoked,
and `evalx` that it is owner invoked only. All three are built to stay present.
