# Layer 5 · Focus

**One file that says what matters right now, and nothing else.**

Memory holds everything the system knows. Focus holds the small part of it that should change today's answers. Without this layer the AI knows a great deal about the owner and still has no opinion about what they should be doing, which is the difference between an archive and an assistant.

It is one file, loaded on every session, and it is where step three of the loop lands. See [feedback-loop.md](feedback-loop.md).

---

## What belongs in it

- **The current priorities**, ranked and few. Three is a working number. When everything is a priority the file has stopped functioning.
- **One line per area of life or work**, saying what is true right now. Not history, status.
- **A single dated table.** Deadlines, gates, the dates that would hurt to miss.
- **The one number that decides the quarter**, whatever it is for this owner: money, a date, a weight, a launch.
- **A pointer, not the content**, for anything that has its own file. A line and a link. Detail lives where the detail lives.

Two rules keep it small enough to be read: **a date lives in the dated table only**, and **if a topic has its own file, focus gets one line about it and nothing more.** An area saying what is true, a table saying when.

---

## What does not belong in it

- **Daily logs.** Those are captures, and they belong in the weekly record. Focus is a state, not a stream.
- **History.** When something stops being current it moves out. Overflow goes to the log rather than being deleted, but it leaves.
- **Project debate.** Options, reasoning and open questions belong with the project. Focus carries the decision only.
- **Random ideas.** They belong in the capture folder. An idea in the focus file has been silently promoted to a priority nobody chose.
- **Anything that has not changed in three months.** If it is permanently true it is a constitution line, not a focus line.
- **Everything.** This is the layer that dies from completeness. A focus file listing forty live items is a to-do list that has taken the name of a priority file, and the AI reading it can no longer tell what to protect.

---

## How you know it is working

**The strongest sign: the AI pushes back.** The owner proposes something new, and the answer names what it would displace, because the file says what is already load bearing. An AI that cheerfully agrees to every new project is one without a focus layer.

Three further signs:

1. **The week starts from the file, not from an empty screen.** The morning question is what is next, and the answer is already written.
2. **It is small enough to read in a minute** and the owner actually reads it. A focus file nobody reads is a memory file with an ambitious name.
3. **It changed after something happened.** A file that has looked the same for two months is not a focus layer, it is a wish list. Movement here is the visible proof that the loop is closed.

---

## Which skill maintains it

**`focus7`** rebuilds it, area by area, from real data, and hands back a diff for the owner to approve rather than rewriting it silently. Run at the weekly review, or after any decision that moves priorities.

**`week7`** is the slow turn of the loop that feeds it: read the week's own records, count the money, name the patterns, decide what changes next week.

**`exit7`** protects it at the end of a session, catching anything that exists only in the chat and asking whether it belongs here.

Between them, the file gets updated because something happened, which is the only reason it should ever change.
